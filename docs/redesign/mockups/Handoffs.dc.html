Resumen ejecutivo

La API de checkout está completa y verificada: sesiones idempotentes, reserva de stock y confirmación de pago por webhook. Frontend puede consumir los endpoints contra el entorno de staging; el contrato está congelado hasta el archivado.

Artefactos

design.md openapi/checkout.yaml svc-orders#412

Decisiones

  • La sesión de checkout caduca a los 15 minutos y libera el stock.
  • Los errores de pago se devuelven como 402 con código de motivo normalizado.

Riesgos

  • medioEl webhook puede llegar antes que la redirección del usuario.

Instrucciones para frontend

  1. Usa el cliente generado desde openapi/checkout.yaml; no escribas fetch a mano.
  2. Muestra el estado «procesando» mientras la sesión esté en pending_payment.
  3. Cubre el reintento de pago rechazado (tarea 2.4) antes de pedir verificación.
