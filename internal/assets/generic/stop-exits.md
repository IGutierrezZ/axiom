**Stops and exits.** A stop is a point where the orchestrator presents what it just produced and waits for a human decision before any further work: every SDD block-review gate except integration (spec, design, tasks, and each role-apply) of a `checkpointed` change. A `continuous` change has no stops. Every stop offers exactly three exits, always in this order:

1. **Iterate:** keep working on the current artifact and present the stop again. There is no limit to the iterations.
2. **Approve, publish and stop:** approve the artifact with `axiom sdd gate record --hand-off`, publish the change documents, hand the next phase to another person, and stop. The session never starts the next phase. Code pushes, pull requests and merges remain yours.
3. **Approve, publish and continue:** approve the artifact with `axiom sdd gate record`, publish the change documents, and continue yourself with the next phase. Code pushes, pull requests and merges remain yours.

"Publish" in exits 2 and 3 is `axiom sdd publish`, run once right after the record with the invocation it returns: it commits only the documentation paths of the change and pushes only the change branch to `origin` (in the specs repository of a `multirepo`, its integration branch), never forced. The stop names that remote and branch, so choosing exit 2 or 3 is the explicit authorization of that push with the git credentials already configured, and of nothing else. A refused publication, such as `code_commits_unpublished` after a role-apply, never undoes the approval: present it as information, with the push command it returns for the human. Whoever continues runs `git fetch origin` (or `axiom branch ensure --fetch` with the user's authorization) and `axiom branch ensure --change <name>`, which adopts the published branch; no merged pull request is needed.

Pushing code, `fetch`, opening a pull request, and merging still belong to the human: present the exact commands and data, and never run them yourself. With the `engram` or `none` artifact store the artifacts are not files: exit 2 is not available and exit 3 publishes nothing, so offer only exits 1 and 3. The person who picks up a handed-off phase starts the next phase without reviewing the previous one again.
