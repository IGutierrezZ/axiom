Integraciones en el panel de Axiom: cómo se va a construir

Este resumen no sustituye al documento: lo que se aprueba es el md.

Qué cambia

Hoy, conectar Axiom con Azure DevOps exige editar un fichero de configuración a mano y escribir órdenes en la terminal. Con este cambio, la persona lo hace todo desde el panel web: activa la integración, guarda su clave de acceso, prueba la conexión y arranca un cambio a partir de una tarea de Azure DevOps. Antes de que el panel maneje esa clave, se refuerza su seguridad.

Para quién

Para quien coordina el trabajo y quiere configurar la integración sin tocar ficheros, y para cualquier persona que quiera ver, en cada cambio, la tarea de origen, las horas imputadas y lo que queda pendiente de enviar a Azure DevOps.

El proceso, antes y después

AntesDespués
Se edita el fichero de configuración a mano.Se rellena un formulario que comprueba cada valor antes de guardarlo.
La clave de acceso se guarda desde la terminal.Se escribe una vez en el panel y queda en el almacén seguro del sistema; nunca vuelve a mostrarse.

Las decisiones principales

D-01 · prov:WEB:1

Una política de contenido estricta

El panel solo cargará código y estilos propios. Para lograrlo se retiran los ocho sitios que tenían estilos escritos dentro de la propia página y el pequeño programa que elige el tema claro u oscuro pasa a su propio fichero. Una prueba automática impide que vuelvan a aparecer.

D-02 · prov:WEB:1 · prov:WEB:2

Una única barrera de seguridad para todo el panel

Toda respuesta del panel lleva las mismas protecciones, también las de error. Cualquier petición que cambie algo, y cualquier consulta de integraciones, debe venir del propio ordenador y del propio panel; si no, se rechaza antes de leerla. Esto también protege acciones que ya existían y hoy no lo comprobaban.

D-03 · RF-TOP-21 · RF-TOP-22

La configuración de la integración, en el mismo catálogo de ajustes

Los campos de Azure DevOps se generan a partir de la descripción del propio plugin, sin repetir sus valores a mano. Se guardan por la misma vía que el resto de ajustes, que conserva los comentarios del fichero y lo valida entero antes de escribirlo. La clave de acceso nunca forma parte de ese catálogo.

D-04

Reutilizar lo que ya hace la terminal

Probar la conexión, descubrir los tipos y estados de Azure DevOps y arrancar un cambio desde una tarea reutilizan exactamente la lógica de las órdenes de terminal, a través de una pieza intercambiable. En las pruebas esa pieza se sustituye por un doble, así que nunca se llama al servicio real.

D-05 · prov:WEB:5 · prov:WEB:6

Esperas acotadas

Las operaciones que hablan con Azure DevOps tienen un tiempo máximo propio (45 segundos para probar o descubrir y 120 para arrancar un cambio). Si se supera, la persona recibe un aviso claro. Si cierra la página, la operación se detiene. Un doble clic no lanza dos operaciones a la vez.

D-06 · prov:WEB:3 · prov:WEB:4

La clave de acceso solo entra, nunca sale

La clave viaja una sola vez hacia el panel y se guarda en el almacén seguro del sistema. Las respuestas solo dicen de dónde se obtiene (variable de entorno, almacén, ausente o almacén no disponible). Borrarla exige una confirmación explícita, porque la comparten todos los proyectos de la persona. Si el sistema no tiene almacén, el panel explica qué variable de entorno usar.

D-07 · prov:WEB:8

Una pestaña de integración en cada cambio

Cada cambio, también los archivados, muestra su tarea de origen, la tarea de cada rol con su estimación y sus horas, lo que falta por imputar, lo que queda pendiente de enviar y quién decidió cada paso. Lo pendiente de enviar se muestra de forma resumida, sin datos internos ni mensajes técnicos.

D-08 · prov:WEB:9 · H-20

Arrancar un cambio desde una tarea de Azure DevOps

Al crear un cambio se puede pegar el número o el enlace de una tarea. El panel sigue los mismos pasos que la terminal. Si algo falla después del primer paso, ofrece «Reintentar» y «Descartar», y descartar siempre pide confirmación. Igual que el alta actual del panel, no fija todavía el modo de trabajo del cambio: lo fija después el asistente al retomarlo. Esta lectura se declara como desviación del texto del requisito y se revisará en la verificación.

D-09 · prov:WEB:10

Enlaces seguros a la tarea

El enlace «Abrir en Azure DevOps» solo aparece si la dirección es una dirección web normal y segura, y se abre en otra pestaña. El nombre del servicio sale de la descripción del plugin, no está escrito a mano.

D-10 · prov:WEB:7 · RF-WEB-18

Una pantalla «Integraciones» que no conoce ningún servicio concreto

La pantalla se dibuja a partir de la descripción de cada plugin. Probar y descubrir usan siempre lo que ya está guardado. Lo descubierto se ofrece como sugerencia y nunca borra un valor ya configurado. Los ajustes de nombres de rama siguen en «Ajustes del proyecto», con un enlace desde aquí.

Lo que queda fuera o a medias

H-05

No hay forma automática de abrir un navegador real en las pruebas: que el panel se vea bien con la nueva política se comprobará a mano en la verificación.

H-09

Una clave rechazada y un fallo de red comparten el mismo código de error; el mensaje sí los distingue.

H-12

No se limita la frecuencia de las peticiones: el panel es local y de una sola persona.

H-19

Si se recarga la página a mitad de un arranque, se recupera volviendo a dar la misma tarea; no hay una lista de arranques a medias.

Cómo se entrega

En seis bloques, cada uno con sus pruebas: seguridad (el primero), catálogo, conexión con el servicio, pantalla, pestaña del cambio y arranque desde una tarea. Todo va en una única propuesta de integración del código.

Glosario

Clave de acceso (PAT)
Contraseña personal que Azure DevOps entrega para que Axiom actúe en nombre de la persona.
Plugin
Pieza que conecta Axiom con un servicio externo concreto; hoy, Azure DevOps.
Política de contenido (CSP)
Lista que indica al navegador qué código y qué estilos puede cargar la página.
Almacén seguro
Lugar del sistema operativo donde se guardan contraseñas de forma protegida.
Pendiente de enviar (outbox)
Avisos que Axiom tiene preparados para Azure DevOps y aún no ha podido entregar.
