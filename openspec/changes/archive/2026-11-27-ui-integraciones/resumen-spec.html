Integraciones en el dashboard

Este resumen no sustituye al documento: lo que se aprueba es el md.

Qué cambia y para quién

Hoy, conectar Azure DevOps exige editar ficheros a mano y usar la terminal. Con este cambio, cualquier persona del equipo puede activarlo, guardar su clave de acceso (PAT), probar la conexión y empezar un cambio desde un work item, todo desde el dashboard local. Antes de manejar claves, el servidor se cierra frente a webs ajenas.

Seguridad primero

Cabeceras de seguridad prov:WEB:1

Toda respuesta lleva una política de contenido estricta, ninguna cabecera que abra el servidor a otros orígenes y el script de tema deja de estar incrustado en la página.

Peticiones solo locales prov:WEB:2

Las operaciones que modifican algo y cualquier consulta de integraciones se rechazan si vienen de un servidor u origen ajeno.

Conexión con el gestor de trabajo

Estado de la integración prov:WEB:3

El dashboard muestra la configuración, la identidad y de dónde viene la clave (entorno, almacén del sistema o ninguna), pero nunca la clave.

Guardar y eliminar la clave prov:WEB:4

La clave se guarda solo en el almacén del sistema y nunca en axiom.yaml. Si el sistema no tiene almacén, se explica qué variable de entorno definir.

Probar conexión prov:WEB:5

Comprueba la clave, muestra quién eres y, si hay varias identidades posibles, permite elegir una.

Descubrir prov:WEB:6

Rellena las listas desplegables con lo que ofrece el gestor de trabajo, sin escribir ningún fichero.

Pantallas nuevas

Pantalla «Integraciones» prov:WEB:7

Se genera a partir de la descripción de cada plugin: activación, conexión y campos. Las plantillas de rama siguen en «Ajustes del proyecto».

Pestaña «Integraciones» del cambio prov:WEB:8

Muestra el work item enlazado, las tareas por rol con su estimación y el tiempo imputado, las operaciones pendientes de enviar y quién hizo cada cosa. También en cambios archivados.

Empezar un cambio desde un work item prov:WEB:9

Con un plugin activo, el alta pide el identificador o la URL del work item. Si algo falla a medias, se puede reintentar o descartar, y descartar solo ocurre si la persona lo pide.

Enlace «Abrir en Azure DevOps» prov:WEB:10

Solo aparece si la dirección es http o https y se abre en una pestaña nueva.

Control automático de claves filtradas prov:WEB:11

Cada ruta nueva queda clasificada en la prueba que busca claves en las respuestas, y esa prueba debe seguir en verde.

Requisitos existentes que se ajustan

Navegación RF-WEB-07

Se añaden «Integraciones» y la pestaña del cambio.

Quién puede escribir RF-WEB-10

integrations se edita solo por ajustes; la clave, por su ruta propia; todo exige origen y servidor locales.

Pantalla de Ajustes RF-WEB-18

No pinta integraciones y enlaza a «Integraciones».

API de ajustes RF-WEB-19

Incluye las claves de integración y rechaza las que el plugin no declara.

Catálogo de claves RF-TOP-21

Incluye las claves de cada plugin, tomadas de su descripción y nunca la clave de acceso.

Escritor de axiom.yaml RF-TOP-22

Edita integrations con las mismas garantías: conserva comentarios, valida todo y escribe de forma atómica.

Flujo antes y después

Glosario

PAT
Clave personal de acceso a Azure DevOps.
CSP
Política que limita qué puede cargar y ejecutar una página.
Manifiesto
Descripción de lo que configura un plugin de integración.
Outbox
Cola de operaciones pendientes de enviar al gestor de trabajo.
Staging
Preparación provisional de un cambio, conservada hasta reintentar o descartar.
