## Reglas de ejecución (aplican a todas las fases)

1. **Un commit por unidad de trabajo.** Cada commit cierra con Conventional Commit en castellano (`tipo(ámbito): resultado`), sin atribución de IA ni `Co-Authored-By`. Las pruebas y la documentación van en el mismo commit que el comportamiento (skill `work-unit-commits`). Cada commit compila y deja en verde las pruebas de los paquetes que toca.
2. **Cierre de commit.** Cada tarea «Cierre del commit» registra: el comando focalizado y su resultado exacto, el arnés de ejecución (o `N/A` con motivo), el límite del commit (ficheros y comportamiento revertibles sin trabajo ajeno) y el mensaje del commit, tomados de la tabla de la rebanada.
3. **Cierre de rebanada y de PR.** La última tarea de cada rebanada ejecuta la batería: `go build ./...`, `go vet ./...`, `go run ./internal/gofmtcheck`, `bash scripts/deadcode-ratchet.sh` (nunca con `--update`), `go test ./internal/cli -run 'TestEveryProductionRefusalNamesResolutionOrDeclaresByDesign|TestRefusalRatchet' -count=1`, `go test ./... -count=1` y la comparación de `git status --porcelain` con el estado previo. El ratchet de deadcode se evalúa en cada corte de PR: un commit intermedio puede dejar una función sin llamador hasta el commit siguiente del mismo PR. El script analiza con `GOOS=linux`; ante una función nueva inalcanzable, compararla con el resultado de la tarea P0.4 antes de concluir y nunca actualizar `.deadcode-baseline.txt`.
4. **Alcance prohibido.** No se escribe en el checkout principal de este repositorio ni se usan `EnterWorktree` ni `ExitWorktree` (todas las rutas son absolutas dentro del worktree de la rama `inc/inc-25-ramas-y-worktrees-por-topologia`). No hay operaciones remotas: ni `push`, ni PR, ni `fetch` contra red, ni `ls-remote`; las pruebas con `--fetch` usan un remoto desnudo local o una ruta inalcanzable. No se modifica `internal/reviewtransaction/**` (código compartido con upstream, R9; solo se consumen `AcquireAuthorityFileLock` y `ReplaceFileAtomic`), ni `docs/archive/ROADMAP.md`, ni `.deadcode-baseline.txt`. En `internal/cli`, `internal/sddstatus`, `internal/kickoff` e `internal/dashboard` el código compartido solo recibe costuras de pocas líneas: el código nuevo va en ficheros nuevos. Archivar `inc-23-knowledge-profile` es una tarea aparte y queda fuera de este plan; tampoco se tocan `openspec/specs/**` (los deltas los aplica `sdd-archive`), salvo las ediciones a mano de la tarea S12.26.
5. **Marcador `(read-only)`.** Toda ruta entre comillas invertidas en una casilla cuenta como objetivo de edición; las rutas que una tarea solo lee llevan `(read-only)` justo detrás. Ninguna tarea cita rutas fuera del worktree entre comillas invertidas.
6. **Presupuesto de ~400 líneas por tarea:** heurística de planificación, no criterio de aceptación ni tope. Nunca se omiten pruebas ni se parte artificialmente para ajustarse.
7. **Skills de apoyo al aplicar:** `skills/work-unit-commits/SKILL.md` y `internal/assets/skills/chained-pr/SKILL.md` para estructurar commits y PR; `internal/assets/skills/go-testing/SKILL.md` en toda tarea con pruebas, también en las de TUI, donde se prueba con `Model.Update` directo (sin `teatest`).
8. **Goldens.** Se regeneran con `go test ./internal/components/ -run TestGolden -update` (y `go test ./internal/tui/ -update` cuando cambien goldens de la TUI) en el commit que cambia el texto; se inspecciona el diff y se vuelve a ejecutar sin `-update`. Nunca se resuelven a mano.
9. **Pruebas con git real.** Repositorios temporales con `git init -b main` en `t.TempDir()`, entorno aislado (`HOME` y `USERPROFILE` temporales, `GIT_CONFIG_GLOBAL` vacío, `GIT_CONFIG_NOSYSTEM=1`, `GIT_TERMINAL_PROMPT=0`), remoto desnudo local para `origin/main` y sin red. Patrón a seguir: `internal/specbaseline/main_test.go` y `internal/cli/sdd_integrate_test.go` (read-only). Las pruebas que ejecutan git real respetan `testing.Short()` (skill `go-testing`); `go test ./...` sin `-short` las ejecuta todas. Los `TestMain` de los paquetes nuevos fijan `workspace.DiscoveryCeilingOverride`; ninguna prueba crea worktrees del repositorio real ni ensucia el checkout.
10. **Windows y portabilidad.** Las rutas `C:/…` que devuelve git se normalizan (`filepath.FromSlash`, `Clean`) y se comparan con `pathidentity.SameDirectory` (los temporales usan nombres cortos 8.3); el registro y la instantánea se escriben con `\n`; `ReadHead` tolera CRLF y espacios finales. Las pruebas que solo tienen sentido en Windows (borrado de un worktree que es el directorio actual, límite real de 220 caracteres) se saltan en otros sistemas; la regla de 220 se prueba además en cualquier sistema con `PathRules{GOOS: "windows"}`.
11. **Mensajes y refusals.** Mensajes y etiquetas en castellano; tokens estables en inglés con su campo hermano `<campo>Label`; toda negativa nombra una continuación ejecutable (orden `axiom ...` con rutas citadas con `pathquote.Quote`) o lleva `refusal:by-design`, de modo que el ratchet de refusals no crezca.
12. **Exención de este cambio.** El `kickoff.yaml` de inc-25 no tiene instantánea, así que las guardas nuevas no lo bloquean a sí mismo (R15): se puede aplicar el cambio con las guardas ya fusionadas.
