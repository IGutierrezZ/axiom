## Notas de cobertura aplicadas

Resuelven huecos de `coverage-review.design.md`:

1. `integration` sin evidencia: el servidor delega en el núcleo (la CLI lo admite). El escenario de prov:WEB:4 «evidencia no válida» se prueba con evidencia malformada (por ejemplo `pr_merged` sin commit) que el núcleo rechaza igual que la CLI. El formulario de la UI siempre exige tipo (tareas 3.1, 6.2, 7.2).
2. `digest` es obligatorio en `POST /api/increments/gate`: 422 tipado si falta. El núcleo lo compara con `ExpectedDigest` (tareas 3.2, 6.1, 6.4).
3. Mapeo explícito del objeto `evidence` del cuerpo HTTP `{kind, commit, baseRef, text}` a `EvidenceKind`, `Commit`, `BaseRef` y `Evidence` de `GateRecordInput` (tareas 6.2, 6.4).
4. Se elimina de D4 el rechazo cuando el último registro es un rechazo del mismo digest: la CLI permite volver a decidir y prov:GAT:1 exige la misma lógica. Se mantienen `gate_not_pending`, `gate_digest_changed` y «puerta ya aprobada» (tarea 3.1, 3.2).
5. `commitReview` ausente equivale a `notify` (doctrina); la UI lo envía explícito y hay prueba de ello (tareas 6.2, 7.1).
6. El reintento de publicación solo exige `checkpointed` y `publication.state == pending`, no que el último registro sea una aprobación (tarea 6.2).

Matriz de amenazas de `design.md` (selección del repositorio, estado del commit, estado del push) cubierta por las pruebas RED de 4.1, 6.1 y 2.1; filas `N/A` omitidas.
