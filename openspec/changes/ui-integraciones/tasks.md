Barandillas transversales (aplican a TODA tarea que toque Go):

- Canario de secretos: toda ruta `/api/...` nueva se clasifica en `secrets_canary_test.go` (`TestEveryDashboardRouteIsClassifiedForTheSecretsCanary`).
- Trinquete de código muerto: `scripts/deadcode-ratchet.sh`; todo exportado nuevo debe ser alcanzable desde `main`.
- Trinquete de rechazos en `internal/cli`: `TestEveryProductionRefusalNamesResolutionOrDeclaresByDesign` (resolución nombrada o `// refusal:by-design`).
- `TestImportsDirection` y `TestAdapterAssemblyImportRules` en verde (`go test ./internal/integrations -run 'TestImportsDirection|TestAdapterAssemblyImportRules'`).
- Sin `t.Parallel()` en pruebas que usen `freePort`, el hub o estado de paquete.
- Ninguna prueba llama a Azure DevOps real (`adotest`, doble de `integrationstest`, doble de `IntegrationsGateway`).
- No compilar binarios sueltos (nada de `go build -o`); solo `go test` y `go vet` focalizados.
- Cada commit lleva su código, pruebas y docs juntos; no se ejecuta la suite completa en local.
